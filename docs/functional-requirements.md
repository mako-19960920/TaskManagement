# 機能要件

画面の見た目と操作の細かい手順は [screen-design.md](screen-design.md)、テーブルは [database-design.md](database-design.md) に書く。

## 1. 機能一覧

### 1.1 表示と保存

| ID | 要件 |
| --- | --- |
| F-01 | `tasks` が空のままサーバーを起動したとき、次の6件を入れる。やること: 「買い物リストを作る」「メールを返す」。進行中: 「企画書の下書き」「資料を読み直す」。完了: 「会議室を予約する」「日程を共有する」 |
| F-10 | 追加は `POST /api/tasks` で1件ずつ登録する。削除、ボタン移動、ドラッグ移動、カードの日付変更の直後は、3列のカードの文章、日付、順番を `PUT /api/tasks` で保存する。書き込みは1つずつ順番に行い、前の書き込みが終わってから次を送る。保存に失敗したときは「保存できませんでした。サーバーとデータベースを確認してください。」と表示し、画面のカードは操作した直後のまま残す |
| F-11 | ページを開いたとき、`GET /api/tasks` の並びでカードを表示する。API から読めないときは「ボードを読み込めませんでした。サーバーとデータベースを確認してください。」と表示する |

### 1.2 カードの操作

| ID | 要件 |
| --- | --- |
| F-02 | 「やること」の入力欄に文章を入れて「追加」を押すと、登録できたあとで、その列の末尾にカードが増える。日付を入れたときだけ、その日付もカードに出す。日付は空でも追加できる。登録を待つあいだは「追加」を押せない。登録に失敗したときは「追加できませんでした。サーバーとデータベースを確認してください。」と表示し、カードは増やさず、入力欄の文字を残す |
| F-03 | 文章の前後の空白は除く。空白だけの入力ではカードを追加しない |
| F-04 | 追加に成功したら、文章と日付の入力欄を空にして、そのまま続きを入力できる状態にする |
| F-05 | どの列のカードでも「削除」を押すと、そのカードだけが消える。確認画面は出さない |
| F-06 | 各カードに、今いる列以外への移動ボタンを出す。ボタン名は「やることへ」「進行中へ」「完了へ」 |
| F-07 | 移動ボタンを押すと、そのカードは行き先の列の末尾へ移る。移ったあとは、その列用のボタンを隠す |
| F-08 | カードの文章をドラッグして列の上で離すと、その列へ移る。同じ列の中の並べ替えにも使う。離した位置がカードの中央より上ならその前、どのカードよりも下なら末尾に入る |
| F-09 | 削除ボタン、移動ボタン、日付の入力欄の上では、ドラッグを開始しない |
| F-12 | 各カードの日付の入力欄で、日付をあとから変えたり消したりできる |

### 1.3 検索

| ID | 要件 |
| --- | --- |
| F-13 | 画面上部の検索フォームで、キーワード、状態、優先度、期限の範囲を指定して「検索」を押すと、条件に合うタスクだけを3列に出す。条件はどれも省略できる |
| F-14 | 検索中は、件数を「検索結果：○件（検索中は列の移動のみできます）」と表示する。0件のときは「該当するタスクはありません」と表示する |
| F-15 | 検索中も、移動ボタンとドラッグで列を移せる。移した結果は保存し、検索結果にもすぐ反映する |
| F-16 | 検索中は、追加欄、削除ボタンを出さず、日付の入力欄は変更できなくする |
| F-17 | 「解除」を押すと、検索前のボードに戻る |
| F-18 | 検索に失敗したとき（期限の範囲が逆など）は、「検索できませんでした。条件を確認してください。」と表示する |

## 2. API

すべて `http://localhost:8080/api/tasks` の下にある。やり取りは JSON で、文字コードは UTF-8 である。

| メソッド | パス | 内容 | エラー |
| --- | --- | --- | --- |
| GET | `/api/tasks` | 全件を、列（todo → in_progress → done）と並びの順で返す | |
| GET | `/api/tasks/{id}` | 1件を返す | 無ければ 404 |
| GET | `/api/tasks/status/{status}` | その列のカードを返す | `todo`、`in_progress`、`done` 以外は 400 |
| GET | `/api/tasks/search` | 条件に合うタスクを返す（2.1） | 値が不正なときは 400 |
| POST | `/api/tasks` | タスクを1件登録する（2.2）。作れたら 201 | 値が不正なときは 400 |
| PUT | `/api/tasks` | 画面の3列ぶんの配列で、タスクをまとめて置き換える（2.3） | |

### 2.1 検索の条件

条件はどれも省略できる。指定したものをすべて満たすタスクだけを、`GET /api/tasks` と同じ並びで返す。

| パラメータ | 意味 |
| --- | --- |
| `keyword` | タイトルか説明に含む文字。部分一致で、大文字小文字を区別しない。`%` と `_` も文字として探す |
| `status` | `todo`、`in_progress`、`done` |
| `priority` | `high`、`medium`、`low` |
| `dueFrom`、`dueTo` | 期限の範囲。`YYYY-MM-DD` で、両端を含む。範囲を指定すると、期限のないタスクは除かれる |

値が不正なとき、`dueFrom` が `dueTo` より後のときは 400 を返す。

```
GET /api/tasks/search?keyword=メール&priority=high
```

### 2.2 1件登録（POST）

本体は次の形である。必須は `title` だけで、ほかは省略できる。

| 項目 | 意味 | 省略したとき | 400 になるとき |
| --- | --- | --- | --- |
| `title` | タイトル。前後の空白は除く | 省略できない | 空、空白だけ、255 文字を超える |
| `description` | 説明文 | null | |
| `priority` | `high`、`medium`、`low` | `medium` | それ以外の値 |
| `dueDate` | 期限。`YYYY-MM-DD` | null | 形が違う、存在しない日付（2月30日など） |

```json
{ "title": "請求書を送る", "priority": "high", "dueDate": "2026-11-20" }
```

状態は `todo`、順番は「やること」でいちばん後ろのタスクの `position` に 1 を足した値（列が空なら 0）にする。件数ではなく最大の `position` を使うのは、途中の番号が抜けていても重ならないようにするためである。

作れたら 201 を返す。`Location` ヘッダーに作ったタスクの URL（`/api/tasks/{id}`）を入れ、本体に作ったタスク（2.4 の形）を返す。

### 2.3 まとめて保存（PUT）の本体

画面の3列を、やること・進行中・完了の順に、それぞれ上から並べた配列で送る。

| 項目 | 意味 |
| --- | --- |
| `id` | 保存済みのカードの ID。まだ保存していないカードは null |
| `key` | 画面が付けた識別子。データベースには保存しない |
| `title` | カードの文章 |
| `dueDate` | 期限。`YYYY-MM-DD` か null |
| `status` | `todo`、`in_progress`、`done` |
| `position` | 列の中の順番。0 から |

```json
[
  { "id": 1, "key": "1", "title": "買い物リストを作る", "dueDate": null, "status": "todo", "position": 0 },
  { "id": null, "key": "6f1c…", "title": "メールを返す", "dueDate": "2026-10-26", "status": "todo", "position": 1 }
]
```

保存のきまりは次のとおりである。

- 送られた配列で `tasks` を置き換える。配列に無いカードは削除する。
- タイトルの前後の空白を除いて空になった要素は保存しない。
- `dueDate` が `YYYY-MM-DD` のときだけ日付を保存し、それ以外は日付なしにする。
- ページを開いただけでは書かない。

### 2.4 応答の形

`GET`、`POST`、`PUT` の応答の要素は、次の形である。`PUT` の応答だけ、送られた `key` をそのまま返す。画面はそれを使って、新しい `id` をカードに結び付ける。`GET` と `POST` では `key` を付けない。

```json
{ "id": 2, "title": "メールを返す", "description": null, "priority": "medium", "dueDate": "2026-10-26", "status": "todo", "position": 1, "createdAt": "2026-11-02T12:00:00", "updatedAt": "2026-11-02T12:00:00" }
```
