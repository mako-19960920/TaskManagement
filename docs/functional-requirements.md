## 1. 機能一覧

### 1.1 表示と保存

| ID | 要件 |
| --- | --- |
| F-01 | `tasks` が空のままサーバーを起動したとき、次の6件を入れる。やること: 「買い物リストを作る」「メールを返す」。進行中: 「企画書の下書き」「資料を読み直す」。完了: 「会議室を予約する」「日程を共有する」 |
| F-10 | 操作するたびに、そのタスク1件だけを API で保存する。追加は `POST /api/tasks`、移動と並べ替えは `PUT /api/tasks/{id}/position`、日付の変更は `PUT /api/tasks/{id}/due-date`、非表示と表示に戻すは `PUT /api/tasks/{id}/hidden`、編集は `PUT /api/tasks/{id}`、削除は `DELETE /api/tasks/{id}`。ほかのタスクは送らないので、ほかの画面で追加したタスクを消さない。画面を先に変えてから送り、書き込みは1つずつ順番に行う。保存に失敗したときは「保存できませんでした。サーバーとデータベースを確認してください。」（削除は「削除できませんでした。…」）と表示し、書き込みが全部終わったあとにサーバーの最新の内容を読み直す。ほかの画面で削除されていた（404）ときは「ほかの画面で削除されたタスクがありました。最新の内容を読み込みます。」と表示して読み直す。ただし削除の 404 は成功として扱う |
| F-11 | ページを開いたとき、`GET /api/tasks` の並びでカードを表示する。API から読めないときは「ボードを読み込めませんでした。サーバーとデータベースを確認してください。」と表示する |

## 2. API

すべて `http://localhost:8080/api/tasks` の下にある。やり取りは JSON で、文字コードは UTF-8 である。エラー（400・404 など）のときは、理由を「2.9 エラーの応答」の形で返す。

| メソッド | パス | 内容 | エラー |
| --- | --- | --- | --- |
| GET | `/api/tasks` | 全件を、列（todo → in_progress → done）と並びの順で返す | |
| GET | `/api/tasks/{id}` | 1件を返す | 無ければ 404 |
| GET | `/api/tasks/status/{status}` | その列のカードを返す | `todo`、`in_progress`、`done` 以外は 400 |
| GET | `/api/tasks/search` | 条件に合うタスクを返す（2.1） | 値が不正なときは 400 |
| POST | `/api/tasks` | タスクを1件登録する（2.2）。作れたら 201 | 値が不正なときは 400 |
| PUT | `/api/tasks/{id}/position` | タスクを1件、別の列や同じ列の別の位置へ移す（2.6） | 無ければ 404、状態の値が違うときは 400 |
| PUT | `/api/tasks/{id}/due-date` | 期限だけを変える（2.7） | 無ければ 404、形が違うときは 400 |
| PUT | `/api/tasks/{id}/hidden` | 非表示かどうかだけを変える（2.8） | 無ければ 404、`hidden` を省略したときは 400 |
| DELETE | `/api/tasks/{id}` | タスクを1件削除する（3.2）。削除できたら 204 | 無ければ 404 |
| PUT | `/api/tasks` | 3列ぶんの配列で、タスクをまとめて置き換える（2.3）。配列に無いタスクは削除する。**画面からは使わない**（ほかの画面で追加したタスクを消してしまうため）。データをまとめて入れ直すときだけ使う | タイトルが 255 文字を超えるときと、状態の値が違うときは 400 |
| PUT | `/api/tasks/{id}` | タスクを1件編集する（2.5）。タイトル・説明・優先度・期限を置き換える | 無ければ 404、値が不正なときは 400 |

### 2.1 検索の条件

条件はどれも省略できる。指定したものをすべて満たすタスクだけを、`GET /api/tasks` と同じ並びで返す。

| パラメータ | 意味 |
| --- | --- |
| `keyword` | タイトルか説明に含む文字。部分一致で、大文字小文字を区別しない。`%` と `_` も文字として探す |
| `status` | `todo`、`in_progress`、`done` |
| `priority` | `high`、`medium`、`low` |
| `dueFrom`、`dueTo` | 期限の範囲。`YYYY-MM-DD` で、両端を含む。範囲を指定すると、期限のないタスクは除かれる |

値が不正なとき、`dueFrom` が `dueTo` より後のときは 400 を返す。

```
GET /api/tasks/search?keyword=メール&priority=high
```

### 2.2 1件登録（POST）

本体は次の形である。必須は `title` だけで、ほかは省略できる。

| 項目 | 意味 | 省略したとき | 400 になるとき |
| --- | --- | --- | --- |
| `title` | タイトル。前後の空白は除く | 省略できない | 空、空白だけ、255 文字を超える |
| `description` | 説明文 | null | |
| `priority` | `high`、`medium`、`low` | `medium` | それ以外の値 |
| `dueDate` | 期限。`YYYY-MM-DD` | null | 形が違う、存在しない日付（2月30日など） |

```json
{ "title": "請求書を送る", "priority": "high", "dueDate": "2026-11-20" }
```

状態は `todo`、順番は「やること」でいちばん後ろのタスクの `position` に 1 を足した値（列が空なら 0）にする。件数ではなく最大の `position` を使うのは、途中の番号が抜けていても重ならないようにするためである。

作れたら 201 を返す。`Location` ヘッダーに作ったタスクの URL（`/api/tasks/{id}`）を入れ、本体に作ったタスク（2.4 の形）を返す。

### 2.3 まとめて保存（PUT）の本体

画面の3列を、やること・進行中・完了の順に、それぞれ上から並べた配列で送る。

| 項目 | 意味 |
| --- | --- |
| `id` | 保存済みのカードの ID。まだ保存していないカードは null |
| `key` | 画面が付けた識別子。データベースには保存しない |
| `title` | カードの文章 |
| `dueDate` | 期限。`YYYY-MM-DD` か null |
| `status` | `todo`、`in_progress`、`done` |
| `position` | 列の中の順番。0 から。非表示のカードも並びの中に入れて数える |
| `hidden` | 非表示か（`true` / `false`）。省略したときは、保存済みのカードは今の値のまま、新しいカードは `false` |

```json
[
  { "id": 1, "key": "1", "title": "買い物リストを作る", "dueDate": null, "status": "todo", "position": 0, "hidden": false },
  { "id": null, "key": "6f1c…", "title": "メールを返す", "dueDate": "2026-10-26", "status": "todo", "position": 1, "hidden": false }
]
```

保存のきまりは次のとおりである。

- 送られた配列で `tasks` を置き換える。配列に無いカードは削除する。
- タイトルの前後の空白を除いて空になった要素は保存しない。
- タイトルが 255 文字を超える要素が1つでもあれば、何も変えずに 400 を返す。状態の値が違う要素があるときも 400 を返し、何も変えない。
- `dueDate` が `YYYY-MM-DD` のときだけ日付を保存し、それ以外は日付なしにする。
- ページを開いただけでは書かない。

### 2.4 応答の形

`GET`、`POST`、`PUT` の応答の要素は、次の形である（`DELETE` は本体を返さない）。`PUT /api/tasks` の応答だけ、送られた `key` をそのまま返す。画面はそれを使って、新しい `id` をカードに結び付ける。ほかの応答では `key` を付けない。

```json
{ "id": 2, "title": "メールを返す", "description": null, "priority": "medium", "dueDate": "2026-10-26", "status": "todo", "position": 1, "hidden": false, "createdAt": "2026-11-02T12:00:00", "updatedAt": "2026-11-02T12:00:00" }
```

### 2.5 1件の編集（PUT /api/tasks/{id}）

本体は次の形である。送った値で置き換える。

| 項目 | 意味 | 省略したとき | 400 になるとき |
| --- | --- | --- | --- |
| `title` | タイトル。前後の空白は除く | 省略できない | 空、空白だけ、255 文字を超える |
| `description` | 説明文。前後の空白は除く | なし（null） | |
| `priority` | `high`、`medium`、`low` | `medium` | それ以外の値 |
| `dueDate` | 期限。`YYYY-MM-DD` | なし（null） | 形が違う、存在しない日付 |

```json
{ "title": "請求書を送る", "description": "月末まで", "priority": "high", "dueDate": "2026-11-30" }
```

- 状態（`status`）、順番（`position`）、非表示（`hidden`）は変えない。
- 成功したら 200 と、編集後のタスク（2.4 の形）を返す。更新日時は新しくなる。
- その id のタスクが無ければ 404、値が不正なら 400 を返し、何も変えない。

### 2.6 移動（PUT /api/tasks/{id}/position）

```json
{ "status": "in_progress", "beforeId": 7 }
```

| 項目 | 意味 |
| --- | --- |
| `status` | 行き先の列。`todo`、`in_progress`、`done`。それ以外は 400 |
| `beforeId` | このタスクの前に入れる。null か、行き先の列に無い（ほかの画面で消えたなど）ときは末尾に入れる |

- 元の列と行き先の列の `position` を、0 からの連番に振り直す。同じ列の中での並べ替えにも使う。
- ほかのタスクは消さない。非表示のタスクも並びの中に入れて数える。
- 成功したら 200 と、移したタスク（2.4 の形）を返す。

### 2.7 期限（PUT /api/tasks/{id}/due-date）

```json
{ "dueDate": "2026-12-01" }
```

`dueDate` が null か空なら、期限なしにする。`YYYY-MM-DD` の形でないとき、存在しない日付のときは 400 を返し、何も変えない。成功したら 200 と、変えたタスクを返す。

### 2.8 非表示（PUT /api/tasks/{id}/hidden）

```json
{ "hidden": true }
```

`hidden` は `true`（非表示）か `false`（表示）。省略したときは 400。列の中の順番は変えない。成功したら 200 と、変えたタスクを返す。

### 2.9 エラーの応答

エラーのときは、RFC 9457（Problem Details）の形で、理由を日本語で返す。`Content-Type` は `application/problem+json` である。

```json
{ "title": "入力した値が正しくありません", "status": 400, "detail": "タイトルは必須です", "instance": "/api/tasks", "field": "title" }
```

| 項目 | 意味 |
| --- | --- |
| `title` | エラーの種類（下の表） |
| `status` | HTTP のステータス（400、404 など） |
| `detail` | 何が間違っているか。送られた値も入れることがある |
| `instance` | 呼んだパス |
| `field` | 間違えた項目（`title`、`priority`、`dueDate`、`hidden`、`status`、`dueFrom`、`dueTo`、`id` など）。項目が決まらないエラーでは付けない |
| `type` | 標準の値（`about:blank`）なので省略する。RFC 9457 では、省略は `about:blank` と同じ意味 |

| status | title | 起きるとき | detail の例 |
| --- | --- | --- | --- |
| 400 | 入力した値が正しくありません | 登録・編集・期限・非表示・まとめて保存の値が正しくない | 「タイトルは必須です」「タイトルは 255 文字までです」「優先度は high / medium / low のいずれかです」「期限は YYYY-MM-DD の形です」「非表示は true か false です」 |
| 400 | 検索条件が正しくありません | 検索の条件が正しくない | 「優先度は high / medium / low のいずれかです（送られた値：urgent）」「期限（から）が期限（まで）より後です（2026-12-31 〜 2026-12-01）」 |
| 400 | 状態の値が正しくありません | 状態が `todo`・`in_progress`・`done` 以外 | 「状態は todo / in_progress / done のいずれかです（送られた値：later）」 |
| 400 | 本体の形が正しくありません | 本体を JSON として読めない | 「本体を JSON として読めませんでした。形と値の種類を確認してください」 |
| 400 | パスやパラメータの値が正しくありません | id が数字でないなど | 「id は数字です（送られた値：abc）」 |
| 404 | タスクが見つかりません | その id のタスクが無い | 「id が 9 のタスクはありません」 |

そのほか、Spring が出すエラー（許可していないメソッドの 405 など）も同じ形で返す（`title` と `detail` は英語）。

## 3. 削除

### 3.1 決まり

| 項目 | 決まり |
| --- | --- |
| 操作 | カード、詳細画面、非表示欄の「削除」ボタンを押す。そのカードだけが消える |
| 確認 | 消す前に「削除していいですか？」と、消すカードの文章、「削除すると元に戻せません。」を出す。「削除する」で消す。「やめる」、Esc キー、確認画面の外側のクリックでは消さず、保存もしない。確認の出し方は 3.3 |
| 検索中 | 検索結果からも削除できる。検索結果の表示と、ボードの同じカード（id で探す）の両方から消し、件数を1減らす（F-15） |
| 画面 | 「削除する」を選んだ直後に、画面からカードを消す |
| 保存 | `DELETE /api/tasks/{id}`（3.2）で、そのタスクだけを削除する。ほかのタスクは送らないので、ほかの画面で追加したタスクを消さない。ほかの書き込みと同じく、1つずつ順番に送る（F-10） |
| データベース | `tasks` の行ごと消す（物理削除）。同じ列の後ろのタスクの `position` を詰めて、0 からの連番を保つ |
| 元に戻す | できない。ごみ箱や「元に戻す」はない |
| ほかの画面ですでに削除されていたとき | 404 が返るが、成功として扱う。エラーは出さない |
| 失敗したとき | 「削除できませんでした。サーバーとデータベースを確認してください。」と表示する。書き込みが全部終わったあとにサーバーの最新の内容を読み直すので、消えていないカードは元の位置に戻る |

### 3.2 削除 API（DELETE /api/tasks/{id}）

```
DELETE /api/tasks/{id}
```

本体は送らない。

| 場合 | 応答 |
| --- | --- |
| 削除できた | 204（本体なし） |
| その id のタスクが無い | 404 |
| id が数字でない | 400 |

サーバーは、次の順で処理する。1つのトランザクションで行い、途中で失敗したら何も変えない。

1. id のタスクを探す。無ければ 404 を返す。
2. その行を `tasks` から消す（物理削除）。
3. 同じ列（同じ `status`）の残りのタスクの `position` を、0 からの連番に振り直す。

### 3.3 確認の出し方

確認の出し方は2つある。`frontend/src/config.ts` の `confirmStyle` で切り替える。はじめは `"dialog"` である。

| 値 | 出し方 | 特徴 |
| --- | --- | --- |
| `"dialog"` | アプリ内の確認画面（HTML の `<dialog>`） | アプリと同じ見た目。開いているあいだは後ろの画面を操作できない。はじめは「やめる」が選ばれている。見た目は [screen-design.md](screen-design.md) の「4. 寸法と色」 |
| `"browser"` | ブラウザ標準の確認（`window.confirm`） | 文言は「削除していいですか？」、空行、「「カードの文章」」、「削除すると元に戻せません。」。ボタンは「OK」と「キャンセル」。見た目はブラウザごとに違い、変えられない |

どちらの出し方でも、ボードからの削除と検索結果からの削除の両方で確認する。

## 4. 非表示

タスクを消さずに、ボードから一時的に隠す。

| 項目 | 決まり |
| --- | --- |
| 非表示にする | カードの「非表示」を押す。確認は出さない（あとで戻せるため）。押した直後にボードから消え、非表示欄に移る |
| 非表示欄 | ボードの下に「非表示のタスク（○件）」を置く。押すと開き、もう一度押すと閉じる。はじめは閉じている。列の順（やること → 進行中 → 完了）、列の中の並び順に出す |
| 表示に戻す | 非表示欄か、検索結果のカードの「表示に戻す」を押す。元の列の元の位置に戻る |
| 削除 | 非表示欄からも削除できる。削除の前に確認する（3.1） |
| 保存 | 非表示にしても、列の並びの中に残したまま `hidden` だけを `true` にし、`PUT /api/tasks/{id}/hidden`（2.8）で送る。並びの中に残すので、表示に戻すと元の位置に出る。データベースの `hidden` 列に残り、開き直しても非表示のまま |
| ほかのカードを動かしたとき | 非表示のカードは消えない。並びの中での前後の関係も変わらない |
| 検索 | 非表示のタスクも、条件に合えば検索結果に出す。「非表示」の印を付け、ボタンは「表示に戻す」にする。検索中に非表示にしたり表示に戻したりしても、件数は変わらない |
| 検索中の非表示欄 | 出さない（非表示のタスクも検索結果に出るため）。解除すると出る |

## 5. タスク詳細

カードを押すと「タスク詳細」の画面を開く。画面の見た目は [screen-design.md](screen-design.md) の UI-16 と、末尾の「タスク詳細の画面（UI-16）の見た目」の表に書く。

### 5.1 開き方と閉じ方

| 項目 | 決まり |
| --- | --- |
| 開く | カードを押す。ボタン（詳細・非表示・削除・移動）と日付の入力欄の上で押したとき、ドラッグしたときは開かない。キーボードでは、カードの「詳細」ボタンで開く |
| 閉じる | 右上の「×」、Esc キー、画面の外側のクリック。編集中に閉じたときは、編集した内容を保存しない |
| 開いているあいだ | 後ろの画面は操作できない |
| 検索中 | 検索結果のカードからも開ける。詳細画面での操作は、検索結果とボードの両方に反映する |
| 保存していないカード | まだ id がないカードは開かない |

### 5.2 見るとき

| 項目 | 出すもの |
| --- | --- |
| タイトル | カードの文章。右に「編集」ボタン |
| 非表示の印 | 非表示のタスクのときだけ「非表示」 |
| ステータス | 「やること」「進行中」「完了」のボタン。今の列のボタンを選んだ状態にする。ほかのボタンを押すと、その列の末尾へ移す（移動ボタンと同じ） |
| 説明 | 説明文。改行もそのまま出す。ないときは「（なし）」 |
| 優先度 | 「高」「中」「低」の色の印 |
| 期限日 | 「2026年11月30日」の形。ないときは「（なし）」 |
| 作成日・更新日 | 「2026/11/2 8:12」の形 |
| 削除 | 押すと確認を出し（3.3）、「削除する」で消して詳細画面を閉じる。確認画面は詳細画面の上に出る |

### 5.3 編集するとき

「編集」を押すと、タイトル・説明・優先度・期限日の入力欄になる。

| 項目 | 決まり |
| --- | --- |
| 入力欄 | タイトル（1行、255 文字まで）、説明（複数行）、優先度（高・中・低から選ぶ）、期限日（日付） |
| 保存 | 「保存」を押すと `PUT /api/tasks/{id}`（2.5）で送る。ほかの書き込みと同じ列に並べ、1つずつ順番に送る。保存を待つあいだは「保存」を押せない |
| 入力チェック | タイトルが空（空白だけ）なら「タイトルを入力してください。」と出し、送らない |
| 成功したとき | 見る表示に戻り、新しい値を出す。ボードのカード（検索中は検索結果のカードも）にも反映する |
| 失敗したとき | 見つからないとき（404）は「このタスクは見つかりませんでした。ほかの画面で削除された可能性があります。」、値が不正なとき（400）はサーバーが返した理由（例：「タイトルは 255 文字までです。」。理由がないときは「入力した内容を確認してください。」）、それ以外は「保存できませんでした。サーバーとデータベースを確認してください。」と出す。入力した内容は残す |
| キャンセル | 「キャンセル」で、保存せずに見る表示に戻る |
